# 探空气球资料组装台（Sounding Assembly）

本地应用：接收探空气球传感器按时间上报的气压、温度、湿度、位置与仪器状态包，
组装每次探空，区分**上升 / 漂浮 / 下降 / 终止**四个运动阶段，从原始资料派生
**标准压力层**和带依据的**质量标志**，并在浏览器里展示时线、高度/气压剖面、
分支转移与每个标志的证据。人工判定与自动识别**分层保存**；新算法重跑只重建
草稿，**不能改写已签字发布的纵向剖面**。

## 运行

依赖安装：

```bash
go mod download
```

演示（自动化测试 + 启动服务）：

```bash
go test ./... -count=1 && go run ./cmd/server --listen 127.0.0.1:5340
```

浏览器打开 <http://127.0.0.1:5340>。SQLite 数据库默认写在 `sounding.db`
（可用 `--db` 或环境变量 `SOUNDING_DB` 改位置）。

页面左侧“模拟器”可一键初始化一班含全部异常的模拟航班，按 1 包 / 8 包 / 一次全部
投递（队列本身是乱序的），或**重放**完全相同的投递序列。

## 目录

- `internal/domain`：包、点、分支、标准层、质量标志与缺失原因的领域定义。
- `internal/store`：SQLite 持久化（原始证据只增不改、草稿/发布分离、乐观锁判定）。
- 去重/分类逻辑位于 `internal/store/packets.go`（按设备序号）。
- `internal/assembly`：排序、运动分支分类、气压反向、结冰、GPS 断点、终止，
  以及人工判定覆盖与冲突候选轨迹规划。
- `internal/profile`：标准压力层派生（等压观测 / ln(p) 插值 / 缺失原因）。
- `internal/service`：批次接收 → 重建草稿；发布单独事务。
- `internal/simulator`：可乱序、可重放的合成输入（含全部异常）。
- `internal/api` + `internal/api/web`：HTTP API 与内嵌的纯原生浏览器界面。
- `cmd/server`：服务入口。

## 数据模型与版本纪律

`raw_packets` 是**只增**的原始证据，任何流程都不修改其字节。每次收到批次：

1. 先把整批包作为证据落库（批次接收）；
2. 再用全部证据 + 当前有效人工判定，**删除旧草稿并重建新的草稿版本**。

`versions` 中每个版本不可原地修改；`published_at` 只会在发布事务中写一次。
发布时把该版本的标准层整份复制进 `published_layers` 冻结表。因此迟到包、重放、
人工改判、算法重跑都只会产生新草稿，**已发布的层物理上不会被触碰**。
重复发布同一版本返回 409。

自动证据写 `findings`，人工签字写 `judgments`，两者互不覆盖；组装时人工判定
作为覆盖项叠加（分支带 `manual` 来源与 `MANUAL_PHASE` 标志）。

## 时序去重口径

- 去重键为**设备序号 + 包序号** `(device, seq)`。
- 载荷指纹为包内容规范化 JSON 的 SHA-256（观测时间截断到秒）。
  - 同 `(device, seq)` 且**指纹相同** → 重试 `DUP_RETRY`：只保留首次到达观测，
    后续重试仍记入原始证据并计数。
  - 同 `(device, seq)` 且**指纹不同** → 冲突 `DUP_CONFLICT`：**绝不平均**，
    生成候选 A（最早到达载荷）/ 候选 B（另一载荷）两条候选版本。
- 当某设备“更大序号已到达之后”该包才到，记为迟到 `LATE_PACKET`。迟到包参与
  新版本组装；在用户重新发布之前，旧的已发布层结保持不变。
- 冲突的人工处理：对某个 seq 选择一个可信载荷（`variant_choice`）后候选折叠为
  单一草稿；选择“保留两条轨迹”（`retain_both`）则两个候选都保留。

## 运动分支口径

点按**星上观测时间**（其次 seq、到达时间、指纹）排序，计算逐点气压倾向
（hPa/分钟，用相邻点窗口）：

- 持续升压倾向 → 下降；持续降压倾向 → 上升；倾向绝对值小于漂浮阈值 → 漂浮。
- 倾向由持续下降翻转为持续上升且保持若干点 → 气球爆裂，之后为下降支。
- 仪器状态字出现 `terminated/term/end_of_sounding` → 该点及其后为**终止**，
  终止点保留在时线上但不派生标准层。
- 短于最小持续长度的相位毛刺会被吸收到相邻分支；人工区间判定强制该区间相位，
  不参与毛刺吸收。
- 每个**同相连续段**是一个分支（branch id）。上升与下降即使在同一气压相遇也是
  不同分支，编号单调递增，页面“分支转移”按序展示来源是自动还是人工。

## 气压短时反向

单点气压相对前后趋势反向（上升中突升压 / 下降中突降压）且幅度超过阈值，标
`PRESSURE_REVERSAL`。这种点**不能作为插值端点**。若它的气压恰好等于标准层，
按“等压观测优先”仍采用观测值，但层上继承该标志，页面可看到依据。

## 湿度传感器结冰

- 自动识别：持续至少若干个点 RH ≥ 99.5% 且温度 ≤ 0 ℃，区间标 `ICING`。
- 人工可圈定任意区间（`icing` 判定），标 `ICING` + `ICING_MANUAL`。
- 结冰区间内 **RH 视为无效**：温度仍可插值，RH 不能用结冰点做端点；无法得到
  RH 的层给出缺失原因 `VARIABLE_GAP`。

## GPS 断点

连续无 GPS 高度采样的游程按缺失样本数分两档：

- ≤ 2 个样本：用前后有效定位做**线性**高度/位置插补，点与受影响层标 `GPS_GAP`；
- 更长：标 `GPS_GAP_MISSING`，不插补；落在其中的标准层高度/位置给
  `GPS_LONG_GAP`。气压仍在时，温度/RH 层照常由气压派生，只是高度缺失。

## 标准压力层与插值口径

标准层：1000, 925, 850, 700, 500, 400, 300, 250, 200, 150, 100, 70, 50, 30, 20,
10 hPa，对**每个非终止分支独立**成层。

1. **等压观测优先**：标准层气压与某观测值之差 ≤ 1e-6 hPa 时直接采用观测值，
   层标 `EXACT_OBS`，并继承该点的质量标志。
2. 否则要求在**同一分支**内存在两个气压夹住标准层的**有效**点，按
   **ln(p) 线性插值**，层标 `INTERPOLATED`。端点必须有效：
   - 温度端点温度非空；
   - RH 端点 RH 非空且不在结冰区间；
   - 高度/位置端点带可用 GPS（短断点插补值可用，长断点缺失不可用）。
3. **上升与下降同压力点绝不混合平均**，也不跨爆裂点/分支边界插值。
4. 插值得到的观测时间按端点时间以同一分数插值，仅作展示。

## 缺失值口径

无法派生的层**保留行**并写明原因，而不是静默丢弃：

| 原因 | 含义 |
| --- | --- |
| `OUT_OF_RANGE` | 该分支气压范围未覆盖此标准层，不跨分支外推 |
| `NO_VALID_PAIR` | 同分支内没有两个夹住该层的有效气压点（反向点不算端点） |
| `VARIABLE_GAP` | 夹逼点存在，但目标变量在结冰区间或因状态字无效 |
| `GPS_LONG_GAP` | 层位于 GPS 长断点内，高度/位置不可恢复 |
| `EXACT_INVALID` | 存在等压观测，但该观测值本身无效 |
| `TERMINATED` | 仪器终止之后，不派生标准层 |

`GET /api/flags` 返回每个标志与缺失原因的中文解释，页面“质量标志依据”面板
逐条展示当前版本实际用到的标志及其规则。

## 批次接收与发布的事务边界

- 批次接收（`POST /api/soundings/{id}/packets`，模拟器端点同理）一个事务内完成
  证据落账；随后草稿重建是独立步骤。接收失败不会留下半截证据。
- 发布（`POST /api/soundings/{id}/publish`）在**单个事务**内：校验版本未发布 →
  写发布记录 → 复制全部层到冻结表 → 回写发布标记。任一步失败整体回滚，
  **不会出现部分标准层被标记为已发布**；零层版本拒绝发布。

## 两人并发判定

人工判定表按 `(sounding, kind, 区间/序号, 签字人)` 校验。两个分析员对**同一类
判定的重叠时间区间**（或同一冲突 seq）并发签字时，后到的请求得到 **409**，
响应里的 `ranges` 给出对方、修订号与**受影响的开始/结束时间段**，界面弹层提示。
同一分析员自己的新签字不与自己冲突。

## HTTP 摘要

```
GET  /api/health
GET  /api/soundings
GET  /api/soundings/{id}                  # 版本 + 原始证据 + 判定 + 发布信息
POST /api/soundings/{id}/packets          # 单包 {"packet":...} 或 {"packets":[...]}
POST /api/soundings/{id}/rebuild          # 只重跑草稿
GET  /api/versions/{vid}                  # 点+分支+层+证据 的聚合
GET  /api/versions/{vid}/points|layers|branches|findings
GET  /api/soundings/{id}/published        # 冻结层
POST /api/soundings/{id}/publish          # 原子发布
GET/POST /api/soundings/{id}/judgments    # 409 携带受影响时间段
GET  /api/flags                           # 标志/缺失原因口径
POST /api/simulator/start|next|batch|all|replay
GET  /api/simulator/status|queue
```

## 测试

- `internal/store`：重试/冲突去重、迟到标记、并发判定 409。
- `internal/profile`：同分支 ln(p) 插值、上升/下降不混合、等压观测、超界缺失、
  结冰 RH 缺失、反向点不作端点。
- `internal/assembly`：上升/下降分类、终止排除、人工相位覆盖、冲突生成两候选、
  选定版本后候选折叠。
- `internal/simulator`：乱序确定性、重放顺序一致、重试重复、冲突双载荷、迟到
  延迟、结冰与 GPS 断点样本存在。
- `internal/service` / `internal/api`：全量乱序输入 → 候选版本 → 原子发布 →
  重放幂等且冻结层字节不变 → 发布后新证据不影响已发布剖面 → 两人并发 409
  携带时间段。
